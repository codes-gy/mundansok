# 09. 리스크 · 점검 윤리

## 점검 윤리 정책
1. **소유를 인증한 도메인만** 점검한다. 인증 값은 무작위 128비트, 도메인마다 다르다.
2. **공격하지 않는다.** 일반 GET 요청 · TLS 연결 · DNS 조회만 한다. 로그인 시도, 대입 공격, 포트 스캔, 취약점 공격 코드는 범위 밖이며 추가하지 않는다.
3. **찾은 비밀은 저장하지 않는다.** 노출 여부와 근거 요약만 남긴다.
4. **점검받는 쪽이 알아볼 수 있게** User-Agent에 서비스 이름 · 연락처를 넣는다.
5. 점검 항목을 늘릴 때는 QA/SEC가 위 원칙에 맞는지 검토한다.

## 리스크 대응표
| 리스크 | 영향 | 가능성 | 대응 | 담당 |
|---|---|---|---|---|
| 남의 도메인을 점검하는 데 악용 | 높음 | 중간 | DNS TXT 소유 인증, 인증 없이 점검 불가 | PM/BE-L |
| SSRF — 내부망 주소로 요청 유도 | 높음 | 중간 | 요청 전 IP 검사(사설 · 루프백 · 링크 로컬 · CGNAT 차단), 리다이렉트 안 따라감 | QA/SEC |
| DNS 리바인딩(검사 후 IP 변경) | 중간 | 낮음 | 3단계에서 검사한 IP로 직접 연결 | BE-2 |
| 오탐으로 신뢰 하락 | 중간 | 높음 | 본문 서명 판정, 테스트 도메인 30개로 오탐률 측정 | BE-1 · QA/SEC |
| 점검 대상 서버 부하 · 차단 | 중간 | 중간 | 10분 제한, 요청 수 최소화, 5초 타임아웃 | BE-2 |
| AI 설명이 틀린 조치 안내 | 중간 | 중간 | 판정은 규칙만, AI는 규칙이 만든 조치 문구를 풀어 쓰기만, 출처 표시 | BE-1 |
| 일정 지연 | 중간 | 중간 | 스프린트마다 범위 재조정, Should 이하 항목부터 이월 | PM/BE-L |
