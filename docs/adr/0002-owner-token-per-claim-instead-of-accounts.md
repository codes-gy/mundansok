# 계정 대신 등록마다 발급하는 소유자 토큰으로 접근을 묶는다

처음에는 도메인 행 하나에 인증 값 · 인증 상태를 두어, 같은 도메인을 다시 등록한 누구에게나 기존 인증 상태가 넘어갔다. 로그인 · 계정 체계를 만드는 대신, 등록할 때마다 새 등록(`domain_claim`)과 256비트 소유자 토큰(평문은 등록 응답에서 한 번만, DB에는 SHA-256만)을 만들고 인증 · 점검 요청 · 점검 결과 조회를 그 토큰에 묶었다. 소유는 계정이 아니라 DNS로 증명하므로 점검 요청마다 인증 레코드를 다시 확인한다.

근거: 커밋 e261f1e, Flyway `V2__owner_token_and_public_ids.sql`, PR #28. 위협 분석은 [docs/threat-model.md](../threat-model.md) §2 · §3.

## Consequences

- 토큰을 잃으면 재발급 없이 새로 등록 · 인증해야 한다. 웹 화면은 토큰을 `localStorage`에 둔다(XSS 시 유출 위험).
- V2 이전 등록 · 점검(`claim_id`, `public_id`가 null)은 API로 볼 수 없다.
- 나중에 계정을 붙이더라도 "등록 = 소유 주장 한 건, 인증은 DNS로" 모델과 토큰 해시 저장 방식은 유지된다는 전제에서 설계해야 한다.
